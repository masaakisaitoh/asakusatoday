# ASAKUSA TODAY — サイト全体UIの多言語対応 設計

## 位置づけ

[2026-08-15-ui-design.md](./2026-08-15-ui-design.md) で「UI文言はデフォルトで英語」と決めた方針に対する変更。
既存の記事本文翻訳機能（`SUPPORTED_LOCALES` / `useArticleLocale`、[2026-08-17-article-translation-design.md](./2026-08-17-article-translation-design.md)参照）は
記事本文だけが対象で、ヘッダーの「Log in」等のUIチュームは対象外だった。この非対称をなくし、
ヘッダーの言語セレクタを切り替えると記事本文だけでなくUI文言全体も追従するようにする。

**Why:** ユーザーから「Log inなどの表記が多言語対応されていない」との指摘があり、UI文言もロケール切替に連動させる方針に転換した。
**How to apply:** 今後UIに関わる文言を追加する際は、このドキュメントで定義する辞書方式に従い、ハードコードしない。

## スコープ

### 対象

- `layouts/default.vue`（ヘッダー: Log in / Log out / Profile / Map、フッターの`@ASAKUSA TODAY`は固有名詞なので対象外）
- `pages/login.vue`
- `pages/account/create.vue`（現状ハードコードされている日本語文言を多言語辞書に載せ替える）
- `pages/account/import.vue`（同上）
- `pages/profile.vue`（ラベル・性別選択肢・バリデーション文言・エラーメッセージ）
- `pages/index.vue`（"NEWS"見出し、"No articles yet."）
- `pages/articles/[id].vue`（"Source:" / "Sources:"、記事が見つからない場合のエラー文言）
- `components/WeatherCard.vue`（"High {temp}°C · Rain {pop}%"）
- `components/AsakusaMap.vue`（位置情報許可メッセージ、再センターボタンのaria-label）

### 対象外（既知のギャップとして記録）

- `pages/admin/*`: 運営者専用画面のため英語のまま据え置き
- `utils/countries.ts`の国名リスト: 200件超×6言語の翻訳はコストに見合わないため、リストの値（国名）自体は英語のまま。プロフィール画面の「Nationality」ラベルやプレースホルダーのみ翻訳対象にする
- サーバー側（`server/utils/session.ts`の`ログインが必要です`、`server/utils/admin.ts`の`管理者権限が必要です`等）でthrowされるエラーメッセージ: リクエストにロケールを渡してサーバー側で切り替える設計変更が必要になり、本対応とは別軸のスコープになるため今回は対象外。将来対応する場合は本ドキュメントを更新する
- 記事本文そのもの: 既存の`server/utils/articles.ts`の翻訳機構が別途担当しており、変更しない

`Record<TranslationLocale, Record<UiStringKey, string>>` という型にすることで、6言語のうち1つでもキーが抜けているとTypeScriptのコンパイルエラーになる。実行時の網羅性チェックは不要。

`weather.summary`のように変数を含む文言は `High {temp}°C · Rain {pop}%` のように`{name}`プレースホルダーで埋め込む。

### composable

`composables/useUiText.ts`:

```ts
export function useUiText() {
  const { locale } = useArticleLocale()

  function t(key: UiStringKey, params?: Record<string, string | number>): string {
    let text = UI_STRINGS[locale.value][key]
    if (params) {
      for (const [name, value] of Object.entries(params)) {
        text = text.replaceAll(`{${name}}`, String(value))
      }
    }
    return text
  }

  return { t }
}
```

既存の`useArticleLocale()`（ヘッダーの言語セレクタが更新する`useState('locale', ...)`）をそのまま読む。新しいstateは作らない。

### 呼び出し側

各ページ/コンポーネントで `const { t } = useUiText()` を呼び出し、テンプレート内で `{{ t('login.title') }}` のように使う。属性値（aria-label等）でも `:aria-label="t('map.recenterAria')"` のように使う。

## エラーハンドリング

`UI_STRINGS[locale.value][key]`が未定義になるケースは型で防いでいるため、ランタイムのフォールバック処理（例外harmless時のデフォルト文言等）は追加しない。

## テスト方針（TDD）

- `composables/useUiText.test.ts` を先に書く。実際の`useArticleLocale`をスタブして、以下を検証する:
  - ロケールが`en`のとき`t('login.title')`が英語文言を返す
  - ロケールが`ja`のとき同じキーが日本語文言を返す
  - `{temp}`等のプレースホルダーが`params`で正しく置換される
- 既存テストへの影響と対応:
  - `tests/e2e/account-flow.test.ts`: 現在「アカウントを新規作成」「続ける」という日本語ボタン文言をセレクタに使っている。デフォルトロケールが`en`になるため、この対応で英語文言（`createAccount.submit` = "Create account"、`createAccount.continue` = "Continue"）に置き換わる。テストのセレクタ文字列を新しい英語文言に更新する
  - `layouts/default.test.ts`: 既に`useState`/`useArticleLocale`をスタブする仕組みがあるので、同じパターンで問題なく動作するはず。念のため実行して確認する
  - `components/WeatherCard.test.ts`: 現在ハードコードされた"High 29°C" / "Rain 30%"をアサートしている。`WeatherCard.vue`が`useUiText()`を呼ぶよう変更するため、このテストにも`useState`/`useArticleLocale`のグローバルスタブを追加する必要がある。翻訳後の英語文言が現在のアサーションと一致するよう`weather.summary`の英語版を`High {temp}°C · Rain {pop}%`のまま維持し、後方互換を保つ

## 翻訳の品質について

`ja`以外の言語（`ko` / `zh-Hant` / `zh-Hans` / `pt`）はAIが翻訳する。ネイティブチェック済みではないため、公開前に確認することを推奨する（既存の記事翻訳機能と同じ精度レベル）。
