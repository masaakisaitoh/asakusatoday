# ASAKUSA TODAY — アカウント作成時の秘密鍵ダウンロード＆事前説明 設計

## 位置づけ

[2026-08-13-symbol-auth-design.md](./2026-08-13-symbol-auth-design.md) で設計したSymbol認証基盤のうち、
「アカウント新規作成」フロー（`pages/account/create.vue`）に対する追加改善。

現状、新規作成すると秘密鍵が画面に一度だけ表示され、ユーザーが手動でコピー・保存する必要がある。
保存し忘れ・保存先を誤るリスクを下げるため、以下2点を追加する。

1. 鍵を生成する前に、秘密鍵の重要性についての説明を読ませ、同意チェックを必須にする。
2. 鍵生成と同時に、秘密鍵を記載したテキストファイルを自動ダウンロードする。

## スコープ

- `pages/account/create.vue` の画面フロー変更
- 秘密鍵ファイルの自動ダウンロード機能（クライアント側のみで完結）
- 既存の画面表示（`code`要素）・「保存しました」チェックボックスは維持
- `tests/e2e/account-flow.test.ts` の更新（新しい確認チェックボックスの操作が挟まるため）

**スコープ外**

- `pages/account/import.vue`（既存鍵インポート）側の変更（インポート時は既にユーザーが鍵を保有しているため対象外）
- サーバー側の変更（鍵はサーバーを一切経由しないという既存方針を維持するため無し）
- ダウンロードファイルのフォーマット選択肢（JSON等）の追加。txt固定でよい。

## 前提・方針

- 秘密鍵はサーバーに一切送らない。ダウンロード処理はブラウザ内（クライアントサイド）で完結させる。既存の[symbol-auth-design.md](./2026-08-13-symbol-auth-design.md)の「秘密鍵はサーバーに一切保存しない」方針を維持する。
- SSR環境でダウンロード処理が実行されないよう、クライアントサイド限定で発火させる。

## 画面フロー

```
1. ページ表示時：
   - 秘密鍵についての説明文を表示
   - 「内容を理解しました」チェックボックス（初期状態: 未チェック）
   - 「アカウントを新規作成」ボタン（チェックが入るまで disabled）

2. チェックを入れて「アカウントを新規作成」をクリック：
   - 鍵ペアをクライアント側で生成
   - 生成直後、自動でテキストファイルのダウンロードを開始
   - 画面に秘密鍵を表示（既存の code 要素）
   - 「秘密鍵を保存しました」チェックボックス表示（初期状態: 未チェック）
   - 「続ける」ボタン（チェックが入るまで disabled）

3. チェックを入れて「続ける」をクリック：
   - 既存フロー通りログイン処理 → /profile へ遷移
```

## 説明文の内容

事前説明として以下を表示する。

> この秘密鍵はあなたのアカウントの唯一の証明です。
> サーバーには保存されません。紛失すると二度と復元できません。
> 誰にも教えないでください。

## ダウンロードファイル仕様

- ファイル名: `asakusatoday-private-key.txt`（固定名）
- MIMEタイプ: `text/plain`
- 中身:

```
ASAKUSA TODAY - 秘密鍵

この秘密鍵はあなたのアカウントへの唯一のログイン手段です。
再発行・復元はできません。安全な場所に保管し、誰にも教えないでください。

作成日時: YYYY-MM-DD HH:mm:ss
秘密鍵: <64桁hex>
```

- 作成日時はダウンロードするブラウザのローカル時刻を `YYYY-MM-DD HH:mm:ss` 形式で埋め込む（タイムゾーン変換やUTC統一は行わない。ローカル時刻をそのまま人が読める形式にする）。
- ダウンロードは `Blob` + 動的に生成した `<a download>` 要素をクリックする方式で実装する（外部ライブラリ不要）。

## コンポーネント／実装方針

- `pages/account/create.vue` に以下を追加する:
  - `understood` という新しい `ref<boolean>` state（事前説明チェック用）
  - 鍵生成後、自動的にダウンロードをトリガーする処理（`generate()` 内、鍵生成の直後に実行）
  - ダウンロード用のファイル内容組み立てとBlob生成・クリックのロジック
- 新規composableへの切り出しは行わない。ロジック量が小さく、`create.vue` 以外から再利用される見込みがないため、YAGNIに従いページ内に留める。
- `useAccount.ts` / `utils/symbolCrypto.ts` は変更しない。

## エラーハンドリング

- ダウンロードAPI（Blob生成やクリックイベント）自体が失敗するケースは通常のブラウザでは想定しにくいため、特別なエラーハンドリングは追加しない。既存の「画面表示＋手動保存確認チェック」がフォールバックとして機能する。

## テスト方針

- **E2E（`tests/e2e/account-flow.test.ts`）**: 「アカウントを新規作成」ボタンをクリックする前に「内容を理解しました」チェックボックスを入れる手順を追加する。ダウンロード自体のファイル内容検証はE2Eでは行わない（ブラウザのダウンロード動作はテスト環境で検証しにくいため）。
- **ユニットテスト**: ダウンロードファイルの中身を組み立てる関数（秘密鍵＋日時からテキスト生成する部分）を純粋関数として切り出し、その関数に対してユニットテストを書く（フォーマットが期待通りかを検証）。Blob生成・クリック部分自体はテスト対象外とする。
