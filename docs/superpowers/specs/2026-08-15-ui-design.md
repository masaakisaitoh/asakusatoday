# ASAKUSA TODAY — UI設計(Nuxt UI導入・和モダンデザイン)

## 位置づけ

[[2026-08-14-articles-design.md]]・[[2026-08-14-article-pipeline-design.md]] で実装済みの記事一覧・詳細表示、および管理画面(下書き承認)に対して、ビジュアルデザインを与える。今回はCSSフレームワークの選定とビジュアル実装が主眼で、既存のAPI・DBスキーマ・サーバーロジックには手を入れない。

## スコープ

- CSSフレームワーク(`@nuxt/ui`)の導入
- カラーテーマ(藍×朱の和モダン)・タイポグラフィの定義
- 共通レイアウト(ヘッダー・フッター)の新規作成
- 既存ページ(`pages/index.vue`, `pages/articles/[id].vue`, `pages/admin/drafts.vue`)とコンポーネント(`components/ArticleCard.vue`)のビジュアル実装
- UI表示文言の英語化

**スコープ外**

- 記事本文の多言語翻訳機能(将来検討事項。現状はブラウザの自動翻訳に依存する方針)
- API・DBスキーマの変更
- ヘッダーへの管理画面ナビゲーションリンク追加(`/admin/drafts`は直接URLアクセスのみ想定のまま)

## 前提・方針

- ASAKUSA TODAYは基本的に英語圏の読者を対象とするサイト。UI表示文言(見出し・ボタン・エラーメッセージ等)は英語で統一する。既存実装にある日本語文言はこの機会に英語へ差し替える。
- モバイルファーストでレイアウトを組む。
- ダークモードに対応し、OS設定に自動で追従させる。

## アーキテクチャ

- `@nuxt/ui`モジュールを導入する。Tailwind CSSを内包しているため、Tailwind単体の追加導入は不要。
- `nuxt.config.ts`の`modules`に`'@nuxt/ui'`を追加する。DB周りなど他の設定には触れない。
- `app.config.ts`を新規作成し、カラーテーマ(primary=藍、朱はアクセント用途で個別に使用)を定義する。

## コンポーネント

### 1. カラー・タイポグラフィ

- **primary(藍)**: 深い藍(indigo系、900〜950相当の紺)。ヘッダー・主要見出し・リンクの基調色。
- **アクセント(朱)**: 使いどころを絞る。管理画面の「承認」ボタンなど主要アクション、カードホバー時の枠線・影、装飾的な下線に限定して使用。
- **背景**: ライトモードは生成り寄りのオフホワイト、ダークモードは墨に近い濃紺〜チャコール。
- **フォント**: ゴシック体系。OS標準の日本語/英語ゴシックフォントを使用し、Webフォントの追加導入は行わない(読み込み速度を優先)。
- **ウェイト**: 見出しはbold、本文は通常ウェイトで行間を広めに取り、記事本文の可読性を優先する。

### 2. 共通レイアウト(`layouts/default.vue`、新規)

- ヘッダー: ロゴ「ASAKUSA TODAY」のみ。クリックでトップページに戻る。ナビゲーションリンクは置かない。
- フッター: 出典・生成方針についての注記を薄く表示する(例: "Articles are AI-generated from public sources and reviewed by our editors before publishing.")。

### 3. トップページ(`pages/index.vue`、既存を差し替え)

- 記事一覧はカードグリッド表示(モバイル1列 → PC3列)。
- ページネーションは既存の自前実装(前へ/次へ+ページ番号)から`UPagination`コンポーネントに置き換える。`route.query.page`との連携ロジック自体は既存を踏襲する。
- 「記事がありません」等の表示文言は英語("No articles yet."等)に変更する。

### 4. 記事詳細ページ(`pages/articles/[id].vue`、既存を差し替え)

- 本文は読みやすい幅に制限し、横幅いっぱいには広げない。
- 画像 → タイトル → 公開日 → 本文 → 出典リンクの順で表示する。
- 「出典:」等の文言は英語("Source:"等)に変更する。

### 5. 管理画面(`pages/admin/drafts.vue`、既存を差し替え)

- 下書きをカード形式で並べ、タイトル・本文プレビュー・出典・操作ボタンを表示する。
- 「承認」ボタンは朱寄りの実線ボタン("Approve")、「却下」ボタンはアウトラインボタン("Reject")。
- 権限なし時のエラー表示等も英語文言に変更する。

### 6. `ArticleCard.vue`(既存を差し替え)

- `UCard`をベースに再構築する。
- 画像がある場合は`aspect-video`でトリミング表示、タイトルは2行クランプ、公開日をカード下部に配置する。
- ホバー時にうっすらと朱の影/枠を出す。

## データフロー

表示ロジックの差し替えのみであり、API呼び出し(`GET /api/articles`, `GET /api/articles/:id`, `GET /api/admin/drafts`, `POST /api/admin/drafts/:id/publish`, `POST /api/admin/drafts/:id/reject`)のリクエスト・レスポンス形状は変更しない。

## エラーハンドリング

既存のAPI側エラーハンドリング(404、`is_admin`でない場合の403等)はそのまま変更しない。フロントエンド側の空状態・エラー表示の文言のみ英語に統一する。

## テスト方針

- `components/ArticleCard.test.ts`: `UCard`等のNuxt UIコンポーネントを使うようになるため、既存の`global.stubs = { NuxtLink: ... }`と同様の要領でstubsに追加する。表示文言のアサーションは英語文言に更新する。
- `tests/smoke.test.ts`: レイアウト変更後もトップページが期待する文言(現在は"ASAKUSA TODAY")を含むことを確認する。ロゴ文言自体は変更しないため影響は小さい想定だが、実装後に必ず流して確認する。
- 既存のAPI結合テスト(`tests/api/*.test.ts`)・サーバーユーティリティのテスト(`server/utils/*.test.ts`)はロジック変更がないため対象外。
